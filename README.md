# IO-Distribution — Конфигуратор расположения модулей АРКС400

> **EN:** Excel VBA macro that calculates and draws the physical layout of
> АРКС400 controller-cabinet hardware (P410 CPU, DIO64/DIO32 I/O modules,
> KDI/KDO terminal modules, intrinsically-safe barriers) on DIN rails, and
> renders a scaled cabinet drawing on the sheet «1 расположение».
> The single entry point is the macro `СоздатьКонфигуратор` in `Module1.bas`.

---

> **Быстрый вход — для будущих агентов и моделей.** Один VBA-макрос
> `Module1.bas` (Windows-1251, CRLF) читает листы «1» и «Service»,
> расставляет модули АРКС400 по DIN-рейкам и рисует масштабную схему на
> листе «1 расположение»; точка входа — `СоздатьКонфигуратор`. Ключевой
> инвариант — нераспределённых реле не бывает (ошибка 28 при `D13=NO`);
> остальные правила — разделы «Как работает алгоритм» и «Правила,
> подтверждённые владельцем». История правок из README удалена — она
> в git/PR; README описывает только текущее состояние.
>
> **Опоры и проверки (обе команды обязаны проходить перед сдачей):**
> * `python3 tools/vba-lint.py` — 0 ошибок и предупреждений: кодировка
>   cp1251, CRLF, блоки, скобки, `Option Explicit`, вызовы, `Err.Raise`…;
> * `python3 tools/parse-spec.py` — исполняемая спецификация разбора
>   чисел (векторы `ЧислоИзТекста`/`ИзвлечьЧисло`), 0 расхождений;
> * `Module1.bas` ≈ 3,5k строк — не читать целиком, искать по именам
>   функций; в README намеренно нет номеров строк — они устаревают.
>
> **Грабли, проверенные исполнением:**
> * в `.bas` только Windows-1251 — `→`, `…`, `×` в комментариях не
>   встречаются (линтер E01 отловит);
> * потребители ячеек сначала пробуют `IsNumeric` → `CDbl` (зависит от
>   локали), в `ЧислоИзТекста` попадает только невчисловой текст;
> * ранний `Exit Function` возвращает 0/False по типу функции, а не
>   «ничего»;
> * предупреждения по столбцу D выдаёт только `ПроверитьЯчейкуКол` —
>   ровно одно на строку; числа, пустые ячейки и ошибки молчат;
> * зеркало `parse-spec.py` локальную ветку `IsNumeric` не покрывает.

## Быстрый старт

**Требования:** Excel 2010+ (Windows) с разрешёнными макросами.

1. Откройте книгу со листами **«1»** (данные) и **«Service»** (справочник).
2. Импортируйте модуль: `Alt+F11` → File → **Import File…** → `Module1.bas`.
   *Файл сохранён в кодировке Windows-1251 — при импорте через VBE кириллица
   отображается корректно. Не копируйте текст через буфер обмена из редакторов
   в UTF-8.*
3. Заполните лист «1» (см. ниже) и при необходимости лист «Service».
4. Запуск: `Alt+F8` → **`СоздатьКонфигуратор`** → Выполнить.
5. Результат: масштабная схема на листе **«1 расположение»** (создаётся
   автоматически) и сводка «Готово! Шкафов задействовано: N».

Если данных не хватает или они противоречат правилам — макрос показывает
«Ошибка конфигуратора: …» и ничего не рисует (лист результата не портится).

## Лист «1» — исходные данные

### Параметры шкафа

| Ячейка | Смысл | Допустимые значения |
|---|---|---|
| **B18** | Длина рейки, мм | положительное число; допускается текст («2000 мм», «1 500»), дробная часть сохраняется |
| **D18** | Число реек в КАЖДОМ шкафу | 3 или 4 — односторонний шкаф; 6 или 8 — двухсторонний (половина реек фронтальные, половина задние); нечисловой текст разбирается, дробная часть отбрасывается |
| **D19** | Резерв (свободное место) на каждой рейке | 0–90 % (или доля 0–0.9); всё, что ≥ 90 %, ограничивается 90 % |
| **D12** | Компоновка контроллеров | `YES` — в шкафу резервированная **пара P410** (пара делит один комплект реле); `NO`/пусто — один P410 на шкаф |
| **D13** | Отдельный релейно-барьерный шкаф | `YES` — реле и барьеры размещаются в отдельном шкафу (тип «S»); `NO` — всё в общих шкафах |
| **D26** | Количество контроллеров P410 | целое ≥ 0; шкафы создаются по `D12` (по 1 или по 2 P410 на шкаф). Текст в ячейке разбирается, но всегда сопровождается предупреждением |

### Сигналы (для диагностики и типизации барьеров)

| Ячейка | Смысл |
|---|---|
| **V10** | Число Exi-сигналов DI (искробезопасные входы) |
| **X10** | Число NAMUR-сигналов DI |
| **AC10** | Число частотных сигналов DI |
| **AA10** | Число Exi-сигналов DO — по нему универсальные барьеры строки 53 сначала назначаются на сторону DO, остаток — на сторону KDI |

Значения читаются как числа; нечисловой текст разбирается по общим правилам
(см. «Разбор чисел из текста»), отрицательный результат обнуляется — это
режим «сигнал не задан».

### Строки модулей (столбец **C** — наименование, столбец **D** — количество)

| Строки | Что заполняется | Как обрабатывается |
|---|---|---|
| 27 | Прочий модуль | Размещается одиночным элементом |
| 28–29 | Модули TC/RTD | Группа «модуль + его барьеры» (строки 49–50) |
| 30–32 | Модули AI/AO | Группа «модуль + его барьеры» (51, 52) |
| 33 | Модуль DIO | «32» в имени → DIO32 (макс. 4 реле), иначе/«64» → DIO64 (макс. 8 реле) |
| 34–35 | Реле KDI | Связка «реле + его барьеры» |
| 36–37 | Реле KDO | Связка «реле + его барьеры» |
| 47–48 | Отдельные барьеры без семейства | Размещаются одиночными элементами |
| 49–50 | Барьеры TC/RTD | Привязываются к модулям 28–29 (температурные входы) |
| 51 | Барьеры RTD>AI | Привязываются к входам AI модулей 30–32 |
| 52 | Общие барьеры AI/AO | Привязываются к входам AI **и** выходам AO модулей 30–32, а также к выходам AO модулей 28–29 |
| 53 | Универсальные DIO-барьеры | Тип (DI/DO) — по наименованию (`KDI`, `DI`, `NAMUR`, `ЧАСТ`, `ВХ`, `FREQ` / `KDO`, `DO`, `ВЫХ`); неопределившиеся — сначала под AA10 (DO), остаток — KDI |
| 54–55 | Барьеры KDI (в т.ч. NAMUR, частотные) | Привязываются к реле KDI |

Префикс `АРКС400.` в наименованиях отбрасывается автоматически.

### Разбор чисел из текста (`ЧислоИзТекста`)

Общая функция для `B18`, `D18`, столбца `D` (строки 26, 27–37, 47–55) и
ячеек сигналов. Локаль в разборе не участвует: цифры накапливаются
арифметически, поэтому `CDbl`/`CLng` не спотыкаются о разделитель.

| Запись | Результат | Правило |
|---|---|---|
| `2000`, `2000 мм` | 2000 | текст после числа игнорируется |
| `1 500`, `1 500 000` | 1500, 1500000 | одиночный пробел между цифрами — разделитель групп разрядов; группы строго по 3 цифры, первая — 1–3 |
| `1  500`, `12 3456`, `12345 678` | 1, 12, 12345 | группы не по правилам → число обрывается до них |
| `2000,5`, `2000.5` | 2000,5 | «,» и «.» — всегда десятичный разделитель |
| `1,234` | 1,234 | то же правило: это не «одна тысяча» |
| `-500`, `−500` | −500 | «−»/«+» считаются знаком только в начале строки или после пробела (U+2212 приводится к «-») |
| `LPA-340-100` | 340 | дефис внутри наименования знаком не считается |
| `5 шт 160` | 5 | читается первое число, остальное — текст |
| `нет`, пусто | 0 | цифр нет — 0 |

**Сноска:** примеры относятся к тексту, который VBA не считает числом.
Потребители (`B18`, `D18` через `ИзвлечьЧисло`, `ЧитатьКол`, `ЧитатьЧисло`)
сначала пробуют `IsNumeric` → `CDbl` и только при отрицании идут в
`ЧислоИзТекста`. Если `IsNumeric` истинно — работает `CDbl`, и результат
зависит от локали: в en-US `IsNumeric("1,234")` = True, будет 1234, а не
1,234.

Пробелоподобные символы нормализуются: NBSP (U+00A0) и тонкие пробелы
(U+2009, U+200A, U+202F) → обычный пробел.

Целочисленные потребители (`D18`, столбец `D`) проходят через `ИзвлечьЧисло`:
дробная часть **отбрасывается** (`Fix`, не округление — иначе действовало бы
банковское округление `CLng`), выход за диапазон `Long` ограничен крайними
значениями: без ограничения `CLng("99999999999")` давал ошибку 6 (Overflow).

## Лист «Service» — справочник

| Столбец | Назначение |
|---|---|
| **D** | Категория: `module AI` / `module AO` (для аналоговых модулей) |
| **E** | Наименование (сопоставляется с колонкой C листа «1», без учёта регистра и неразрывных пробелов) |
| **F** | Число каналов |
| **H** | Ширина, мм (положительное число) |

Правила поиска:

* **Ширина (H)** ищется по наименованию. Если записи нет — берётся
  встроенный запас и выдаётся предупреждение.
* **Каналы реле (F)** — по наименованию; запас по умолчанию — **8 каналов**
  (KDI/KDO — 8-канальные клеммные модули).
* **Каналы барьеров (F)** — по наименованию; запас по умолчанию — **1 канал**.
* **Аналоговые модули**: AI-каналы читаются из записи с категорией
  `module AI`, AO-каналы — из записи `module AO` (0 каналов допустим —
  направление не поддерживается). Если модуля нет совсем — принимается
  **AI × 8** и выдаётся предупреждение.

Встроенные запасные ширины (мм), если Service не содержит записи:

## Как работает алгоритм

1. **Шкафы P410.** Создаётся столько шкафов, сколько нужно для размещения
   всех контроллеров (по 1 P410, при `D12=YES` — резервированная пара на
   шкаф, каждый на своей фронтальной рейке). Сразу резервируется верхняя
   зона **224 мм**: на рейках с P410 — сам контроллер, на остальных
   фронтальных рейках — «Коммутаторы и БП». Задние рейки двухсторонних
   шкафов (6/8 реек) остаются полными.

2. **Реле, подключаемые к P410** (этап 1.1). В каждый шкаф с P410
   помещается до **4 KDI + 4 KDO** вместе с их барьерами (резервированная
   пара при `D12=YES` делит один комплект). Связка ставится только целиком;
   не поместившаяся связка не считается подключённой.

3. **Остаток реле — модулям DIO** (этап 2). Остаток пересчитывается после
   P410. DIO64 получает до **8** реле, DIO32 — до **4**, в любой пропорции
   KDI/KDO. Все группы, кроме **последней** (последний DIO по порядку
   строк листа), обязаны быть полными. Группа «DIO + реле + барьеры»
   размещается только целиком и только в одном шкафу; если ни в один
   существующий шкаф не помещается — создаётся новый.

4. **Аналоговые модули и барьеры** (этап 2.2). Три прохода: барьеры
   TC/RTD → температурные входы; RTD>AI → входы AI; общий пул AI/AO →
   входы AI и выходы AO (включая AO температурных модулей). Критерий —
   минимальная загрузка каналов модуля. Модуль со своими барьерами
   размещается в одном шкафу.

5. **Нераспределённых реле быть не должно** (этап 2.3). В обычном
   режиме (`D13=NO`) каждое реле обязано обслуживать либо P410, либо
   группу DIO. Остаток — **ошибка данных**: макрос
   останавливается с перечнем оставшихся реле и подсказками, а не
   создаёт отдельный шкаф. Исключение — `D13=YES`: там реле и барьеры
   штатно живут в отдельном шкафу.

6. **Одиночные элементы** (этап 3): оставшиеся модули и барьеры без
   привязки размещаются по первому подходящему месту.

7. **Контроль и отрисовка.** Перед рисованием проверяются инварианты:
   заполнение всех реек без переполнения (сумма ширин элементов
   пересчитывается независимо от накопленного учёта рейки — ошибки
   77/78), целостность связок и групп в пределах одного шкафа и т.п.
   Отдельно сверяется согласованность масштаба отрисовки (ошибка 82).
   Затем на листе «1 расположение»
   строится масштабная схема: контуры шкафов, рейки с метками
   «занято/ёмкость», зоны P410 и «Коммутаторы и БП», резерв, модули с
   наименованиями и легенда.

## Сообщения об ошибках

Ошибки показываются в окне «Ошибка конфигуратора» и прерывают расчёт.
Номер — смещение `vbObjectError + N` (виден в отладчике).

| N | Когда | Что проверить |
|---|---|---|
| 10 | B18 содержит ошибку | Укажите длину рейки |
| 11 | B18 ≤ 0 (в том числе «−500» в тексте) | Длина рейки должна быть положительной |
| 12 | D18 не 3/4/6/8 | Число реек на шкаф |
| 13 | Полезная длина рейки меньше верхней зоны 224 мм | B18, D19 |
| 14 | Ошибка в наименовании модуля (столбец C) | Соответствующая строка |
| 15 | Модуль шире полезной длины рейки | B18, D19, Service!H |
| 16 | D13=YES при наличии DIO | Установите D13=NO для групп DIO |
| 17 | D13=YES при P410 и реле | Реле нельзя оторвать от P410 — D13=NO |
| 18 | D13=YES: модуль TC/RTD и его барьеры разнесены | D13=NO |
| 19 | D13=YES: модуль AI/AO и его барьеры разнесены | D13=NO |
| 20–27 | Внутренние проверки целостности этапов DIO | Не должны возникать; если возникли — сообщите разработчику |
| **28** | **Остались реле, не назначенные ни P410, ни DIO** | Количество реле (строки 34–37) vs число модулей DIO; помещаемость связок в шкафы P410; для отдельного релейного шкафа — D13=YES |
| 30 | Барьер не удалось назначить реле без превышения каналов | Добавьте реле или проверьте Service!F |
| 31 | Не удалось закрепить все реле за DIO | Внутренняя проверка |
| 32 | Недостаточно реле для непоследней группы DIO | Добавьте реле или уменьшите число DIO |
| 33–37 | Внутренние проверки связок | — |
| 40–47 | Связка/группа не помещается или нарушены правила размещения | B18, D18, D19, количества |
| 50–54 | Внутренние проверки планировщика реек | — |
| 60–78 | Нарушены инварианты размещения: неразмещённый элемент, разрыв связки между шкафами, переполнение рейки (77), расхождение учёта `rUsed` с суммой ширин на рейке (78) | Не должны возникать; если возникли — сообщите разработчику |
| 80–81 | Несоответствие числа созданных реек / не хватило реек под P410 | D18 |
| 82 | Служебная: масштаб отрисовки не согласован с высотой верхней зоны | `CTRL_ZONE_MM × MM` должно равняться `CTRL_OFFSET_PX` |
| 90 | Нет шкафов для отрисовки | Заполните данные |

## Предупреждения (не критические)

Собираются в `gWarn` и показываются вместе с итогом «Готово!»:

* резерв D19 ограничен 90 %;
* модуль шире рейки с верхней зоной P410/коммутаторов;
* сигналы DI/DO: не хватает каналов имеющихся KDI/KDO (ориентировочная
  потребность в реле);
* наименование не найдено в Service (ширина/каналы взяты по умолчанию);
* аналоговые барьеры: нет подходящих модулей или превышена ёмкость
  каналов (размещение выполнено условно);
* строка 33: в имени нет 32/64 — принято DIO64;
* `Строка N, столбец D: количество записано текстом ("…"); принято N.` —
  число стояло в тексте, и расчёт его увидел (строки 26, 27–37, 47–55);
* `Строка N, столбец D: "…" — не число; строка не участвует в расчёте.` —
  получить число из ячейки не удалось (цифр нет либо набран 0).

Обычные числа, пустые ячейки и ячейки с ошибкой предупреждений не дают;
на одну строку — не более одного сообщения.

## Правила, подтверждённые владельцем

* **D12=YES** — в шкафу стоит **резервированная пара P410** (горячий
  резерв), и пара **делит один комплект 4 KDI + 4 KDO**. Отдельного
  комплекта на каждый контроллер не требуется.
* Зона «Коммутаторы и БП» (224 мм) резервируется на **каждой
  фронтальной рейке** шкафа P410 — это сделано намеренно.
* **Нераспределённых реле не бывает**: если реле не достались ни P410,
  ни DIO — это ошибка исходных данных, и макрос обязан сообщить об
  этом, а не молча поставить их в отдельный шкаф.

## Технические заметки

* `Module1.bas` хранится в кодировке **Windows-1251** с CRLF. При правках
  вне VBE следите за кодировкой.
* Планировщик укладки: сначала «вся группа на одну рейку», затем
  best-fit-decreasing по блокам, затем полный перебор с отсечениями
  (лимиты: 120 блоков на полный перебор, 300 000 узлов). Если группа не
  помещается целиком в один шкаф — создаётся новый шкаф.
* Связка «реле + барьеры» и группа «DIO + реле + барьеры» могут
  раскладываться по нескольким рейкам, но только в пределах одного
  шкафа.
* `Module1.txt` — устаревшая копия модуля (на ветке `main` уже удалена);
  источником истины считается `Module1.bas`.
* CI: `.github/workflows/vba-lint.yml` запускает `tools/vba-lint.py` по
  всем `.bas`/`.cls` репозитория и `tools/parse-spec.py` — так ловятся
  потерянная индентация, «висячие» ссылки после вычистки кода,
  рассогласование `Err.Raise` и уехавшие правила разбора чисел.
* `tools/parse-spec.py` — зеркало `ЧислоИзТекста` на Python (тот же порядок
  вычислений, без локали). Это спецификация, а не тест VBA: совпадение с
  модулем поддерживает человек, правящий обе части. Ветка `IsNumeric` →
  `CDbl` в потребителях зеркалом не покрывается — она зависит от
  системной локали VBA.
