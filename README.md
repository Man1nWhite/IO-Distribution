# IO-Distribution — конфигуратор раскладки модулей АРКС400

Один модуль VBA — `Module1.bas` (Windows-1251, CRLF): читает листы **«1»**
(данные) и **«Service»** (справочник), раскладывает железо шкафов АРКС400
(P410, DIO64/DIO32, реле KDI/KDO, барьеры) по DIN-рейкам и рисует масштабную
схему на листе **«1 расположение»**. Точка входа — `СоздатьКонфигуратор`.

## Агенту: вход

* **Проверки перед сдачей** (их же гоняет CI, `.github/workflows/vba-lint.yml`):
  * `python3 tools/vba-lint.py` — 0 ошибок и 0 предупреждений: кодировка
    cp1251 + CRLF, баланс блоков, скобки/кавычки, `Option Explicit`, объявления
    и вызовы, метки, `ReDim`, `Err.Raise`, висячие `_`. Каталог E01–E18 /
    W01–W05 с описаниями — в докстринге инструмента; CI падает по ошибкам E*,
    но и W* держат нулём;
  * `python3 tools/parse-spec.py` — 0 расхождений: исполняемая спецификация
    разбора чисел (векторы `ЧислоИзТекста` / `ИзвлечьЧисло`).
* **Навигация:** `Module1.bas` ≈ 3,5k строк, целиком не читать. Искать по
  именам процедур (они русские) и по баннерам секций `'=====`. В README нет
  номеров строк (устаревают) и истории правок (она в git/PR) — только текущее
  состояние.
* **Кодировка:** в `.bas` допустимы только символы Windows-1251, поэтому
  `→`, `…`, `×` в комментариях не писать (`«» — •` можно); линтер поймает как E01.
* **Инвариант №1 — нераспределённых реле не бывает.** Каждое реле обслуживает
  либо P410, либо группу DIO; остаток = ошибка исходных данных (код 28), а не
  повод молча создавать отдельный шкаф. Единственное исключение — `D13=YES`.
* **Подтверждено владельцем, не «улучшать»:** при `D12=YES` резервированная
  пара P410 делит **один** комплект 4 KDI + 4 KDO; верхняя зона 224 мм
  резервируется на **каждой** фронтальной рейке шкафа P410 — намеренно.
* **Локаль не участвует в разборе текста** (§Разбор чисел из текста), но ветка
  `IsNumeric` → `CDbl` у потребителей от локали зависит — это не баг.
* **Ранний `Exit Function`** в функциях возвращает 0 / False по типу, а не
  «ничего»; предупреждения по столбцу D даёт только `ПроверитьЯчейкуКол` —
  ровно одно на строку (числа, пустые и ошибочные ячейки молчат).

## Быстрый старт

Требования: Excel 2010+ (Windows), разрешённые макросы.

1. Книга с листами **«1»** и **«Service»**.
2. `Alt+F11` → File → **Import File…** → `Module1.bas`. Не переносить текст
   через буфер из UTF-8-редакторов — кириллица живёт в Windows-1251.
3. Заполнить «1» (и при необходимости «Service»).
4. `Alt+F8` → **`СоздатьКонфигуратор`** → Выполнить.
5. Итог: схема на листе «1 расположение» (создаётся сам) + «Готово! Шкафов
   задействовано: N».

При нехватке или противоречии данных — «Ошибка конфигуратора: …», лист
результата не портится (рисуем только после успешного расчёта).

## Лист «1» — данные

Параметры шкафа:

| Ячейка | Смысл | Значения |
|---|---|---|
| **B18** | длина рейки, мм | > 0; текст («2000 мм», «1 500») разбирается, дробная часть сохраняется |
| **D18** | реек в **каждом** шкафу | 3/4 — односторонний; 6/8 — двухсторонний (половина реек фронтальные, половина задние); через `ИзвлечьЧисло` — дробная часть отбрасывается |
| **D19** | резерв (свободное место) на рейке | 0–90 % или доля 0–0.9; всё ≥ 90 % ограничивается 90 % |
| **D12** | компоновка контроллеров | `YES` — в шкафу резервированная пара P410 (общий комплект реле); `NO`/пусто — один P410 |
| **D13** | отдельный релейно-барьерный шкаф | `YES` — реле и барьеры в отдельном шкафу (тип «S»); `NO` — всё в общих |
| **D26** | число P410 | целое ≥ 0; шкафы создаются по `D12` (по 1 или 2 на шкаф); текст разбирается, но всегда с предупреждением |

Сигналы (только для диагностики и типизации барьеров): **V10** — Exi DI,
**X10** — NAMUR DI, **AC10** — частотные DI, **AA10** — Exi DO. Читаются как
числа (нечисловой текст — общий разбор), отрицательное обнуляется = «не задан».
По AA10 универсальные барьеры строки 53 сначала уходят на DO, остаток — на KDI.

Строки модулей: **C** — наименование (префикс `АРКС400.` отбрасывается),
**D** — количество.

| Строки | Что | Обработка |
|---|---|---|
| 27 | прочие модули | одиночные элементы |
| 28–29 | модули TC/RTD | группа «модуль + барьеры 49–50» |
| 30–32 | модули AI/AO | группа «модуль + барьеры 51, 52» |
| 33 | DIO | «32» в имени → DIO32 (до 4 реле), иначе/«64» → DIO64 (до 8) |
| 34–35 / 36–37 | реле KDI / KDO | связка «реле + его барьеры» |
| 47–48 | барьеры без семейства | одиночные элементы |
| 49–50 | барьеры TC/RTD | к модулям 28–29 |
| 51 | барьеры RTD>AI | к входам AI модулей 30–32 |
| 52 | общие барьеры AI/AO | к входам AI **и** выходам AO модулей 30–32 и к AO модулей 28–29 |
| 53 | универсальные DIO-барьеры | тип по имени: `KDI`,`DI`,`NAMUR`,`ЧАСТ`,`ВХ`,`FREQ` → DI; `KDO`,`DO`,`ВЫХ` → DO; неопределившиеся — см. AA10 |
| 54–55 | барьеры KDI (в т.ч. NAMUR, частотные) | к реле KDI |

### Разбор чисел из текста (`ЧислоИзТекста`)

Общая функция для `B18`, `D18`, столбца `D` (26, 27–37, 47–55) и ячеек
сигналов. Цифры накапливаются арифметически, поэтому разделитель тысяч не
ломает разбор и локаль в нём не участвует. Зеркало правил —
`tools/parse-spec.py` (спецификация, а не тест VBA): правка в VBA ⇒ правка
зеркала; ветку `IsNumeric` зеркало не покрывает — она локально-зависима.

| Запись | Результат | Правило |
|---|---|---|
| `2000`, `2000 мм` | 2000 | текст после числа игнорируется |
| `1 500`, `1 500 000` | 1500, 1500000 | одиночный пробел между цифрами — разделитель групп; группы ровно по 3 цифры, первая 1–3 |
| `1  500`, `12 3456`, `12345 678` | 1, 12, 12345 | группы не по правилам → число обрывается до них |
| `2000,5`, `2000.5`, `1,234` | 2000,5 · 2000,5 · 1,234 | «,» и «.» — всегда десятичный разделитель (это не «одна тысяча») |
| `-500`, `−500` | −500 | «−»/«+» — знак только в начале или после пробела; U+2212 → «-» |
| `LPA-340-100` | 340 | дефис внутри наименования знаком не считается |
| `5 шт 160` | 5 | читается первое число |
| `нет`, пусто | 0 | цифр нет → 0 |

Пробелоподобные символы нормализуются: NBSP (U+00A0) и тонкие пробелы
(U+2009, U+200A, U+202F) → обычный пробел.

**Потребители сначала пробуют `IsNumeric` → `CDbl`**, и только при отказе идут
в `ЧислоИзТекста`: значит для «числоподобного» текста результат зависит от
локали (в en-US `IsNumeric("1,234")` = True → 1234, а не 1,234). Целочисленные
потребители (`D18`, столбец `D` через `ИзвлечьЧисло`/`ЧитатьКол`) отбрасывают
дробную часть через `Fix` (не округление, иначе работало бы банковское
округление `CLng`) и ограничиваются диапазоном `Long` — без ограничения
`CLng("99999999999")` даёт ошибку 6 (Overflow).

## Лист «Service» — справочник

| Столбец | Назначение |
|---|---|
| **D** | категория: `module AI` / `module AO` (аналоговые модули) |
| **E** | наименование (сверяется с C листа «1», регистр и неразрывные пробелы не учитываются) |
| **F** | число каналов |
| **H** | ширина, мм (> 0) |

* Нет ширины (H) → встроенный запас + предупреждение. Нет каналов реле →
  **8** (KDI/KDO — 8-канальные клеммные модули); нет каналов барьера → **1**.
* Аналоговые модули: AI-каналы из строки с категорией `module AI`, AO-каналы
  из `module AO`; **0 каналов допустим** — направление не поддерживается.
  Модуля в Service нет вовсе → **AI × 8** + предупреждение.

Запасные ширины (мм), если записей в Service нет:

|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|---|
| мм | 35 | 164 | 164 | 157 | 157 | 157 | 157 | 110 | 110 | 100 | 100 | 23 | 67 | 13 | 23 | 23 | 13 | 13 | 13 | 23 |

## Алгоритм (этапы в `СоздатьКонфигуратор`)

1. **Шкафы P410.** По `D26`/`D12` (1 P410 на шкаф либо пара). При создании
   рейки сразу теряют 224 мм: фронтальная рейка с контроллером — на P410,
   остальные фронтальные — на «Коммутаторы и БП» (`SWITCH_RESERVE_ALL_RAILS`);
   задние рейки двухсторонних шкафов не резервируются (`..._BACK_RAILS = False`).
2. **Реле для P410 (этап 1.1).** До 4 KDI + 4 KDO с барьерами на шкаф; при
   `D12=YES` пара делит один комплект. Связка считается занятой, **только**
   если реле и барьеры реально разместились в шкафу.
3. **Остаток реле → DIO (этап 2).** Остаток пересчитывается после этапа 1.1;
   DIO64 — до 8 реле, DIO32 — до 4, пропорция KDI/KDO любая. Все группы, кроме
   последней по порядку строк, обязаны быть полными. Группа «DIO + реле +
   барьеры» размещается целиком и в одном шкафу; иначе создаётся новый шкаф.
4. **Аналог (этап 2.2), три прохода:** 49–50 → входы TC/RTD; 51 → входы AI;
   52 → общий пул AI/AO (в т.ч. AO температурных модулей). Критерий выбора
   модуля — минимальная загрузка каналов; модуль со своими барьерами в одном шкафу.
5. **Остаток реле (этап 2.3).** `D13=NO` → ошибка 28 со списком реле и
   подсказками; `D13=YES` → связки типа «S» штатно в отдельный шкаф.
6. **Одиночные элементы (этап 3).** Остатки без привязки — по первому
   подходящему месту.
7. **Проверки и отрисовка.** Инварианты: заполнение реек без переполнения,
   причём сумма ширин считается независимо от накопленного `rUsed` (ошибки
   77/78); целостность связок и групп в пределах шкафа; согласованность
   масштаба (ошибка 82). Затем — схема: контуры шкафов, рейки с метками
   «занято/ёмкость», зоны P410 и «Коммутаторы и БП», резерв, модули, легенда.

**Карта этапов → процедур** (искать по именам, не по строкам; имена процедур
русские, у укладчика — английские): чтение ячеек — `ЧитатьКол`,
`ПроверитьЯчейкуКол`, `ЧитатьЧисло`, `ЧислоИзТекста`, `ИзвлечьЧисло`;
классификация — `ОчиститьИмя`, `ОпределитьТип`, `Семейство`, `ЭтоБарьер`,
`ТипБарьераDIO`, `РаспределитьОбщиеБарьерыDIO`; справочник — `ШиринаИзService`,
`КаналыИзService`, `КаналыПоКатегории`, `ЁмкостьАналогМодуля`,
`НаправлениеАналогБарьера`, `РаспределитьАналоговыеБарьеры`; шкафы и рейки —
`ДобавитьШкаф`, `РасширитьМассивыРеек`, `НайтиРейку`; связки и реле —
`СформироватьСвязки`, `ТипСвязки`, `СвободноДляDIO`, `СобратьСвязку`,
`ЗакрепитьРелеЗаКонтроллером`, `ReserveDioBundles`, `FreeRelaysForDio`,
`AssignRelaysToDio`; укладка — `РазместитьСвязку`, `РазместитьСвязкуВШкаф`,
`РазместитьГруппуDIO`, `РазместитьАналоговуюГруппу`, `РазместитьОдиночный`,
`TryPlaceGroupInCab`, `TryPlanBlocks`, `SearchBlocks`, `CommitPlan`,
`PlaceModule`, `СуммаДлин`; контроль и чертёж — `ПроверитьРазмещение`,
`НарисоватьРасположение`, `ДобРект`, `ДобТекст`.

## Ошибки

Показываются в окне «Ошибка конфигуратора» и прерывают расчёт. Номер —
смещение `vbObjectError + N` (видно в отладчике); полный список —
`grep -n "vbObjectError + " Module1.bas`.

| N | Когда | Что проверить |
|---|---|---|
| 10 / 11 | B18 — ошибка ячейки / значение ≤ 0 (в т.ч. «−500» в тексте) | длина рейки |
| 12 | D18 не 3/4/6/8 | число реек на шкаф |
| 13 | полезная длина рейки меньше верхней зоны 224 мм | B18, D19 |
| 14 | ошибка в наименовании (столбец C) | соответствующая строка |
| 15 | модуль шире полезной длины рейки | B18, D19, Service!H |
| 16–19 | `D13=YES` конфликтует с раскладкой: есть DIO; есть реле при P410; модуль TC/RTD (или AI/AO) разъезжается со своими барьерами | снять D13=YES |
| **28** | **остались реле, не назначенные ни P410, ни DIO** | количество реле (34–37) vs число DIO; помещаемость связок в шкафы P410; для отдельного релейного шкафа — D13=YES |
| 30 | барьер не влез в каналы реле без превышения | добавить реле, Service!F |
| 31 / 32 | за DIO закреплены не все реле / мало реле для непоследней группы | количества, число DIO |
| 42 / 45 / 47 | связка или группа не помещается целиком даже в пустой шкаф | B18, D18, D19, Service!H, количества |
| 44 / 46 | достигнут предел поиска укладки (лимиты планировщика) | уменьшить группы; лимиты — `PLAN_*` |
| 20–27, 33–41, 43, 50–54, 60–78, 80–81 | внутренние проверки этапов: целостность связок и групп, планировщик реек, инварианты размещения (77 — переполнение рейки, 78 — расхождение `rUsed` с суммой ширин), число реек и место под P410 | не должны возникать; если возникли — сообщить разработчику |
| 82 | `CTRL_ZONE_MM × MM ≠ CTRL_OFFSET_PX` | константы масштаба отрисовки |
| 90 | нет шкафов для отрисовки | данные листа «1» |

## Предупреждения (расчёт не прерывают)

Собираются в `gWarn`, показываются под итогом «Готово!»:

* резерв D19 ограничен 90 %;
* модуль шире рейки с верхней зоной P410/коммутаторов (используются другие рейки);
* сигналы DI/DO: каналов KDI/KDO меньше, чем сигналов (ориентировочная
  потребность в реле);
* наименования нет в Service → ширина/каналы по умолчанию;
* аналоговые барьеры: у модулей нет подходящих каналов (барьеры размещены
  отдельно) либо превышена ёмкость каналов (размещение условно);
* строка 33: в имени нет 32/64 → принято DIO64;
* `Строка N, столбец D: количество записано текстом ("…"); принято N.` —
  число стояло в тексте, расчёт его увидел (строки 26, 27–37, 47–55);
* `Строка N, столбец D: "…" — не число; строка не участвует в расчёте.` —
  цифр нет либо набран 0.

Обычные числа, пустые ячейки и ячейки с ошибкой предупреждений не дают; на
строку — не более одного сообщения.

## Технические заметки

* Планировщик укладки: сначала «вся группа на одну рейку», затем
  best-fit-decreasing по блокам, затем полный перебор с отсечениями (лимиты
  `PLAN_SEARCH_BLOCK_LIMIT` = 120 блоков, `PLAN_NODE_LIMIT` = 300 000 узлов).
  Не влезла в существующий шкаф целиком — создаётся новый.
* Связка «реле + барьеры» и группа «DIO + реле + барьеры» могут раскладываться
  по нескольким рейкам, но только в пределах одного шкафа.
