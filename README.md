# IO-Distribution — конфигуратор раскладки модулей АРКС400 (VBA)

`Module1.bas` (Windows-1251 + CRLF, ≈3,5k строк) читает лист «1» (данные) и
«Service» (справочник), раскладывает железо шкафов АРКС400 (P410, DIO64/DIO32,
реле KDI/KDO, барьеры) по DIN-рейкам и рисует масштабную схему на листе
«1 расположение». Точка входа — `СоздатьКонфигуратор` (запуск `Alt+F8`),
итог — «Готово! Шкафов задействовано: N»; Excel 2010+ (Windows), макросы
разрешены, импорт `Alt+F11 → File → Import File…` (не через буфер из
UTF-8-редактора). При ошибке данных — окно «Ошибка конфигуратора (код N): …»
(N — из таблицы «Ошибки»), расчёт прерван, лист результата не тронут.

## Проверки

```sh
python3 tools/vba-lint.py
python3 tools/parse-spec.py
python3 tools/plan-spec.py
python3 tools/check-readme-map.py
python3 tools/check-sync.py
```

Это ровно те же пять шагов, что в CI, в том же порядке; одной командой на
любой ОС — `python3 tools/check-all.py` (Windows: `py tools\check-all.py`;
`--list` — только перечислить шаги; `./tools/check-all.sh` — обёртка).
Ожидаемый результат: 0 ошибок и предупреждений линтера; 36 тестовых векторов
без расхождений; спецификация планировщика (`tools/plan-spec.py`, зеркало
`TryPlanBlocks`/`SearchBlocks`/`TryPlacePartialSplit` и закрепления связок
за P410, канонические сценарии + рандом со сверкой с брутфорсом) сходится;
все 45 имён из карты процедур ниже существуют в коде
(`tools/check-readme-map.py`, проверка односторонняя: служебные процедуры
вне карты допустимы, их список печатается для аудита); зеркала и обещания
README сходятся (`tools/check-sync.py`: `PLAN_EPS`, `PLAN_NODE_LIMIT`,
`PLAN_SEARCH_BLOCK_LIMIT`, `MAX_LONG` против `tools/*-spec.py`, `defRows` и
`defLensFallback` против таблиц README, константы, названные в README как
«`ИМЯ` = N», против кода, состав команд README и `tools/check-all.py --list`
против шагов CI, счётчики 36/45 против фактических, вывод каждого
`tools/*.py` в pipe с cp1252). Каталог E01–E18 / W01–W05 — в докстринге
линтера.

Инструменты — Python ≥ 3.7 без внешних зависимостей. Вывод всегда UTF-8, и в
консоль, и в pipe/файл: иначе на Windows (Git Bash, `> log`, CI) Python пишет в
cp1251/cp1252 и падает на «↔», «−», «—» с `UnicodeEncodeError`. Новый
инструмент — то же переключение вывода в UTF-8 (последние строки любого
`tools/*.py`); за этим следит `check-sync.py`.

CI `.github/workflows/vba-lint.yml` (actions/checkout@v7, setup-python@v7,
Python 3.12) падает только по ошибкам `E*`; `W*` держат нулём. Кодировка:
в `.bas` допустимы только символы Windows-1251 — `→`, `…`, `×` писать нельзя
(линтер даст E01), `«» — •` можно; CRLF защищён `.gitattributes`
(`*.bas -text` — git не перепишет окончания строк ни при каком `core.autocrlf`).

## Пример: `Example.xlsx`

Пробная книга без макроса (`vbaProject` внутри нет). Листы: `Title`,
`Service`, `1` (данные), `1 схема`, `1 расположение` (результат, в книге
лежит отрисовка прошлого прогона). Конфигуратор читает только «1» и
«Service». Значения примера: `B18`=1800, `D18`=4, `D19`=0,2, `D12`=`Yes`,
`D13`=`No`, `D26` — формула (`ROUNDUP` по `AE10` и `Service`), а конфигуратор
читает **значение** ячейки, а не формулу; при ручном режиме вычислений он сам
пересчитывает книгу (`Application.Calculate`) перед чтением.
Строки вне `defRows` (27–37, 47–55) не читаются — в примере это 38–46
(шлюзы, БП, клеммы и пр.) и 56.

Запуск: сохранить копию как `.xlsm` (или открыть книгу с макросами),
`Alt+F11 → File → Import File… → Module1.bas`, затем `Alt+F8 →
СоздатьКонфигуратор`. **Обновление:** старый модуль сначала удалить (`Alt+F11`
→ правой кнопкой по `Module1` → `Remove Module1…` / «Удалить Module1…», экспорт
не нужен), потом импортировать новый — иначе VBE назовёт его `Module11`, и в
`Alt+F8` окажутся два `СоздатьКонфигуратор` (легко запустить старый). Лист
«1 расположение» при отсутствии создаётся сам
(после листа «1») и **очищается перед отрисовкой целиком** — все фигуры
(`Shapes`) и ячейки, — так что пометки пользователя на нём не переживут
запуск. Если листа «1» или «Service» нет — окно «ОШИБКА: не найден лист …»,
расчёт не начинается.

## Ограничения и инварианты

* **Нераспределённых реле не бывает.** Каждое реле обслуживает либо P410, либо
  группу DIO; остаток = ошибка исходных данных 28, а не молчаливый отдельный
  шкаф. Исключение — `D13=YES` (реле и барьеры штатно в отдельном шкафу «S»).
* `D12=YES`: резервированная пара P410 делит **один** комплект 4 KDI + 4 KDO.
  Нечётное `D26` при этом оставляет один шкаф с одним P410 — предупреждение, не
  ошибка.
* Барьеры строки 51 (`RTD>AI`) подключаются только ко **входам** AI и никогда не
  занимают выходы AO: в общем пуле AI/AO (строка 52) их вклад ограничен
  `mCapAI` модуля.
* Верхняя зона 224 мм резервируется на **каждой** фронтальной рейке шкафа P410
  (`SWITCH_RESERVE_ALL_RAILS=True`, `..._BACK_RAILS=False`), задние рейки полные.
* Все группы DIO, кроме последней по порядку строк, обязаны быть полными.
* Связка «[Реле + его барьеры]» кладётся целиком на одну рейку, пока это
  возможно: сначала разбивается ровно **один** блок группы (по очереди, от
  самого широкого), затем — самый широкий вместе со следующими по ширине;
  полное дробление на элементы — последний фоллбэк.
* Локаль в разборе текста не участвует, но ветка `IsNumeric → CDbl` у
  потребителей зависит от локали.
* Ранний `Exit Function` возвращает 0/False по типу функции, а не «ничего».
* По столбцу D предупреждает только `ПроверитьЯчейкуКол` — ровно одно сообщение
  на строку; числа, пустые и ошибочные ячейки молчат. Количество больше
  `MAX_QTY` (числом или текстом) — ошибка 29 ещё до расчёта.

## Лист «1» — данные

| Ячейка | Смысл | Правила |
|---|---|---|
| B18 | длина рейки, мм | >0; текст («2000 мм») разбирается, дробная часть сохраняется (`Double`, не `ИзвлечьЧисло`) |
| D18 | реек в **каждом** шкафу | 3/4 — односторонний; 6/8 — двухсторонний (половина реек F, половина B); `ИзвлечьЧисло` — дробная часть отброшена |
| D19 | резерв на рейке | 0–90 % или доля 0–0.9; всё ≥90 % → 90 % + предупреждение; текст («20 %») разбирается `ЧислоИзТекста`, всегда с предупреждением |
| D12 | компоновка контроллеров | `YES` — резервированная пара P410 на шкаф; `NO`/пусто — один P410 |
| D13 | отдельный релейно-барьерный шкаф | `YES` — реле/барьеры в шкафу «S»; `NO` — всё в общих |
| D26 | число P410 | целое ≥0; шкафы по `D12`; текст разбирается, всегда с предупреждением |
| V10 / X10 / AC10 / AA10 | сигналы Exi DI / NAMUR DI / частотные DI / Exi DO | для диагностики и типизации барьеров; разбор как чисел, отрицательное → 0 («не задан»); по AA10 универсальные барьеры строки 53 идут сначала на DO, остаток на KDI |

Столбец C — наименование (префикс `АРКС400.` отбрасывается), D — количество:
не больше `MAX_QTY` = 10000 на строку (в том числе D26), иначе ошибка 29 —
это почти наверняка опечатка, а не многочасовой расчёт. Читаются только строки `defRows` = 27–37, 47–55; всё остальное (в примере —
38–46 и 56) конфигуратор не читает.

| Строки | Что | Куда привязывается |
|---|---|---|
| 27 | прочие модули | одиночные элементы |
| 28–29 | модули TC/RTD | группа с барьерами 49–50 |
| 30–32 | модули AI/AO | группа с барьерами 51, 52 |
| 33 | DIO | «32» в имени → DIO32 (до 4 реле), иначе/«64» → DIO64 (до 8) |
| 34–35 / 36–37 | реле KDI / KDO | связка «реле + его барьеры» |
| 47–48 | барьеры без семейства | одиночные элементы |
| 49–50 / 51 | барьеры TC/RTD / RTD>AI | к модулям 28–29 / к входам AI модулей 30–32 |
| 52 | общие барьеры AI/AO | входы AI и выходы AO модулей 30–32 + выходы AO модулей 28–29 |
| 53 | универсальные DIO-барьеры | тип по имени: `KDI DI NAMUR ЧАСТ ВХ FREQ` → DI, `KDO DO ВЫХ` → DO, иначе по AA10 |
| 54–55 | барьеры KDI (в т.ч. NAMUR, частотные) | к реле KDI |

## Разбор чисел из текста (`ЧислоИзТекста`)

Общий для B18, D18, D19, столбца D (26, 27–37, 47–55) и ячеек сигналов. Правила
описаны в комментарии над `ЧислоИзТекста`, исполняемые векторы —
в `tools/parse-spec.py`. `,` и `.` — всегда десятичный разделитель (`1,234` → 1,234, а
не 1234), а пробел — разделитель групп ровно по 3 цифры (`1  500` → 1).

Потребители сначала пробуют `IsNumeric → CDbl` (для «числоподобного» текста
результат локально-зависим: en-US `IsNumeric("1,234")` = True → 1234), и лишь
затем `ЧислоИзТекста`. Целочисленные (`D18`, столбец D) режут дробь через `Fix`
(не округление — `CLng` округлял бы банковски) и ограничивают диапазон `Long`
константой `MAX_LONG` = 2147483647 (иначе `CLng("99999999999")` = ошибка 6,
Overflow; значение константы сверяет `tools/check-sync.py`). NBSP U+00A0 и
тонкие пробелы U+2009/U+200A/U+202F → обычный пробел.

## Лист «Service» — справочник

`D` — категория (`module AI` / `module AO`), `E` — наименование (сверка с C
листа «1»: регистр и неразрывные пробелы не учитываются), `F` — каналы,
`H` — ширина, мм (>0). Нет ширины → встроенный запас + предупреждение; нет
каналов реле → 8 (KDI/KDO 8-канальные), барьера → 1; у аналогового модуля
AI-каналы из `module AI`, AO — из `module AO`, 0 каналов допустим (направление
не поддерживается), модуля нет вовсе → AI×8 + предупреждение. Запасные ширины
(`defLensFallback`), строка → мм: 27=35, 28=164, 29=164, 30..33=157, 34=110,
35=110, 36=100, 37=100, 47=23, 48=67, 49=13, 50=23, 51=23, 52=13, 53=13,
54=13, 55=23.

## Алгоритм (этапы в `СоздатьКонфигуратор`)

1. Шкафы P410 по D26/D12; при создании рейки сразу теряют 224 мм (зона P410 /
   «Коммутаторы и БП»).
2. (1.1) До 4 KDI + 4 KDO с барьерами на шкаф P410; при `D12=YES` пара делит
   один комплект. Связка занята контроллером, **только** если реле и барьеры
   реально разместились в шкафу. Связка кладётся целиком на наименее загруженную
   рейку шкафа, поэтому 4 KDI и 4 KDO расходятся по разным рейкам, а не
   набиваются на первую. Открытый инженерный вопрос: критерий — максимум
   свободного места, а фронтальные рейки урезаны зоной P410 на 224 мм,
   поэтому при равных связках задние рейки заполняются плотнее фронтальных
   (в каноническом сценарии `plan-spec.py`: F/F/B/B = 1/1/3/3). Приоритет
   фронтальных реек (ближе к контроллеру) пока не вводился.
3. (2) Остаток реле пересчитывается после 1.1 и распределяется по DIO (8/4
   реле, пропорция KDI/KDO любая). Группа «DIO + реле + барьеры» целиком и в
   одном шкафу; не влезла в существующие → новый шкаф.
4. (2.2) Аналог, три прохода: 49–50 → входы TC/RTD; 51 → входы AI; 52 → общий
   пул AI/AO (в т.ч. AO температурных). Критерий — минимальная загрузка
   каналов модуля; модуль со своими барьерами в одном шкафу. Занятость от
   прохода 51 переносится в общий пул как `Min(usedAI, mCapAI)`: свободный
   остаток для строки 52 равен `Max(0, mCapAI - usedAI) + mCapAO`, выходы AO
   остаются под строку 52, а превышение прохода 51 не дублируется в `overflow`.
5. (2.3) Остаток связок: `D13=NO` → ошибка 28 со списком реле и подсказками;
   `D13=YES` → в отдельный шкаф.
6. (3) Одиночные элементы — по первому подходящему месту.
7. Проверки инвариантов (переполнение рейки 77, расхождение `rUsed` с суммой
   ширин 78, целостность связок/групп, масштаб 82) и отрисовка: контуры
   шкафов, рейки с «занято/ёмкость», зоны P410 и коммутаторов, резерв,
   модули, легенда.

Укладчик: «вся группа на одну рейку» → best-fit-decreasing по блокам → полный
перебор с отсечениями (`PLAN_SEARCH_BLOCK_LIMIT`=120 блоков). Бюджет перебора
`PLAN_NODE_LIMIT`=300000 узлов — сквозной на одну попытку укладки группы
в шкаф: счётчик узлов общий для целых блоков, обеих фаз мягкого дробления
и фоллбэка на отдельные элементы (раньше лимит был у каждого вызова
`TryPlanBlocks` свой). Поэтому ошибки 44/46 («предел поиска») вместо
45/47 («не помещается даже в пустой шкаф») выбираются по `hitLimit`
последней попытки — на пустом шкафу со свежим бюджетом: упёрся поиск —
исход не доказан (44/46), не упёрся — укладки точно нет (45/47). Связка и группа могут лежать на нескольких
рейках, но только одного шкафа. Если целые блоки не укладываются, работает
`TryPlacePartialSplit`: фаза 1 дробит ровно один составной блок (по очереди,
от самого широкого), фаза 2 добавляет к нему следующие по ширине — так 7 из 8
связок остаются неразрывными; полное дробление на элементы — последний
фоллбэк. Перебор (`SearchBlocks`) отсекает симметричные перестановки блоков
одинаковой ширины: для такого блока рейки перебираются начиная с рейки
предыдущего блока той же ширины.

## Ошибки (`vbObjectError + N`, в окне — «код N»)

Полный список: `grep -n "vbObjectError + " Module1.bas`. Сбой самого
VBA/Excel, не из таблицы, показывается как «ошибка VBA N» — этот номер нужен
для сообщения разработчику.

| N | Когда | Проверить |
|---|---|---|
| 10 / 11 | B18 — ошибка ячейки / значение ≤0 | длина рейки |
| 12 | D18 не 3/4/6/8 | число реек на шкаф |
| 13 | полезная длина рейки < зоны 224 мм | B18, D19 |
| 14 | ошибка в наименовании (столбец C) | строка модуля |
| 15 | модуль шире полезной длины рейки | B18, D19, Service!H |
| 16–19 | `D13=YES` конфликтует: есть DIO; есть реле при P410; TC/RTD или AI/AO разъезжается со своими барьерами | снять D13=YES |
| **28** | реле не назначены ни P410, ни DIO | реле (34–37) vs число DIO; помещаемость связок; нужен отдельный шкаф → D13=YES |
| 29 | количество в строке столбца D больше `MAX_QTY` | ячейка из сообщения (опечатка?) |
| 30 | барьер не влезает в каналы реле | добавить реле, Service!F |
| 31 / 32 | за DIO закреплены не все реле / мало реле для непоследней группы | количества, число DIO |
| 42 / 45 / 47 | связка или группа не влезает целиком даже в пустой шкаф | B18, D18, D19, Service!H, количества |
| 44 / 46 | достигнут предел поиска укладки | уменьшить группу; лимиты `PLAN_*` |
| 20–27, 33–41, 43, 50–54, 60–78, 80–81 | внутренние проверки: целостность связок/групп, планировщик, инварианты размещения, число реек и место под P410 | не должны возникать — сообщить разработчику |
| 82 | `CTRL_ZONE_MM × MM ≠ CTRL_OFFSET_PX` | константы масштаба отрисовки |
| 90 | нет шкафов для отрисовки | данные листа «1» |

## Предупреждения (под итогом «Готово!», расчёт не прерывают)

Резерв D19 ограничен 90 % · `D19: резерв записан текстом ("…"); принято N%.` ·
`D12=YES` при нечётном количестве P410 в D26 (один
шкаф будет с 1 контроллером) · модуль шире рейки с зоной P410/коммутаторов
(возьмутся другие рейки) · DI/DO: каналов KDI/KDO меньше сигналов
(ориентировочная потребность в реле) · наименования нет в Service → ширина и

## Ручная проверка после импорта (VBA в CI не запускается)

1. Импорт `Module1.bas` в книгу с листами «1» и «Service» (`Alt+F11 → File →
   Import File…`; старый `Module1` сначала удалить — см. «Обновление»). Нет
   листа — окно «ОШИБКА: не найден лист …», расчёт не начинается.
2. `Alt+F8 → СоздатьКонфигуратор` на примере: ожидается «Готово! Шкафов
   задействовано: N» **без** блока «ВНИМАНИЕ:».
3. Лист «1 расположение»: контуры шкафов, рейки с «занято/ёмкость», зоны P410
   и коммутаторов, легенда. Повторный запуск не должен накладывать фигуры
   друг на друга (лист очищается перед отрисовкой).
4. Испортить данные (например, `D18`=5) → окно «Ошибка конфигуратора (код 12):
   …», расчёт прерван, лист результата не тронут.
5. Новые проверки: `D19` = текст «20 %» → «Готово!» с предупреждением
   «D19: резерв записан текстом ("20 %"); принято 20%.»; любое количество
   строк 27–37 / 47–55 = 1000000 → «Ошибка конфигуратора (код 29)» с номером
   строки; ручной режим вычислений (Формулы → Параметры вычислений → Вручную)
   и правка входных данных без F9 → результат как после пересчёта.
